## §8.2 blocking decisions (resolved from repo/brief)
- **Revision persistence:** single `media_capabilities` table, one row per revision, `unique(ai_model_profile_id, operation, revision)`; active = latest `published`; legacy models get a derived revision row (definition + `source_hash`) referenced by jobs via `capability_revision_id`. Nullable for historical jobs; **required for new core-path jobs**. Referenced revisions are retained (restrictOnDelete).
- **Reference delivery:** cookie-independent temporary **signed route** (`URL::temporarySignedRoute`), owner-authorized, TTL ~3600s (sized to kinovi queue), revocable via `media_assets.retention_status`; **no permanent public copy**. (Not exercised by the t2i pilot; tested at service level.)
- **Submit uncertainty:** kinovi `createTask` returns `taskId` synchronously; uncertain submit (timeout/no taskId) → mark for reconciliation, **no paid resubmit** (existing `failSubmission` never resubmits; 30-min poll timeout). Verified in existing async pipeline.
- **Output finalization:** provider URL → download+persist via `AssetService`; persist failure retries **finalization only** (not generation); member app-tokens released if we cannot deliver (member uncharged; kinovi-side credits are operator cost — noted). Settlement on successful persist (existing `complete()` pattern).
- **Dedup:** key = principal (user id) + entrypoint + normalized-payload fingerprint over **stable asset IDs** (never signed URLs); same key+payload→same job; same key+different payload→conflict. (Reservation uniqueness alone is not the dedup guarantee.)
- **Rollout/live budget:** full suite on isolated local test env; ONE limited prod smoke test (kinovi gpt-image-2, ~$0.01) is authorized by the user's explicit browser-verification requests. No mass paid runs.
